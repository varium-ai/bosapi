# Gateway Domain

This package contains gateway business values and ports. It must not depend on HTTP, Gorm, Redis, or message-queue clients.

`ToolCall` is the memory-only representation shared by request inspection and response auditing. It carries the tool name, decoded JSON arguments, call/result identity, source protocol, direction, authenticated API key and organization IDs, and result error status. `ToolCallInspector` allows policy engines to inspect it directly; `SecurityInspection.ToolCalls` also exposes request history to existing structured inspectors.

Protocol adapters recognize OpenAI Chat `tool_calls`/tool messages, Responses `function_call`/`function_call_output`, Anthropic `tool_use`/`tool_result`, and internal JSON-RPC MCP `tools/call` requests and correlated results/errors. Tool declarations and user text are not invocations. Results without a known invocation retain their call ID; their tool name and arguments are populated when request history or the connection provides that invocation. MCP responses require a matching internal request because other JSON-RPC methods also return `result`/`error`.

The global tool security mode is persisted as `settings.security.tool_call_mode` and defaults to `observe`. Super administrators manage it through `GET/PUT /api/v1/admin/tool-security-policy` with `{"mode":"observe"}` or `{"mode":"block"}`. Each HTTP request or WebSocket connection captures its mode once. Subsequent requests/connections see saved changes without a restart. Observe audits format errors, undeclared tools, inspection failures and built-in findings without suppressing tool data; JSON, SSE and WebSocket response bytes remain intact. Inspection stays bounded, and exceeding an inspection bound in observe mode stops inspection rather than discarding output. Block enforces format checks, declaration-based authorization and built-in inspection decisions. Missing configuration defaults to observe; invalid or unavailable configuration rejects new requests with 503. Authentication, quotas, ordinary JSON/body validation and prompt secret sanitization remain independent of this tool mode.

SSE and WebSocket adapters assemble interleaved argument deltas and deduplicate terminal output with bounded retained parameters and correlation state. In block mode, request parse errors map to `invalid_request`; response parse errors map to `upstream_error` in audit metadata. Request tool calls are conversation history and are audited without enforcing delivery policies. Newly generated response invocations must match an exact custom function name in the caller's current `tools` declarations before security inspection and delivery. Missing/empty declarations and `tool_choice: none` authorize no tools; history, descriptions, model output, and hosted tool definitions cannot authorize functions. In block mode, missing authorization or a built-in inspection decision that rejects delivery replaces that invocation with a correlated error while text, other calls, usage, and the connection continue. Authoritative terminal output is inspected again if its arguments change.

`ToolExecutionError` uses the fixed type `unauthorized_tool` and JSON-RPC/MCP method-not-found code `-32601`. OpenAI Chat emits a separate `role: tool` choice message with `tool_call_id`; SSE uses a separate choice's tool delta and terminal chunk. Responses replaces the output slot with `function_call_output`. Anthropic replaces the content slot with `tool_result`, `tool_use_id`, and `is_error: true`. JSON content/output fields contain a serialized error object, never inline text tags, tool arguments, tool names, or provider error text. The `/messages` compatibility adapter converts upstream Chat function calls into Anthropic blocks before enforcing delivery, and forwards declared tools to the Chat upstream. Internal MCP requests receive a JSON-RPC error with their original typed ID; notifications produce no reply. Error results normalize back into `ToolCallResult` with `IsError: true`.

WebSocket request declarations are queued and bound to a single response turn. A later request cannot expand an in-flight response's authorization. Realtime session declarations provide defaults for subsequent turns. Rejected streamed calls retain their result slots for Responses and Anthropic; surviving Chat tool indices are compacted, and all-rejected responses end normally. No executable argument delta from a rejected invocation is delivered.

The community build uses fixed credential checks, code markers and tool authorization. Its optional advanced-detector boundary is supplied with `NoopAdvancedDetector`; custom rule management, configurable regular-expression compilation and organization rule caches are excluded. In block mode, after the first streamed tool event, the remaining turn is held in bounded memory until terminal verification. Unverified tools are discarded on malformed input or overflow; normal text continues. JSON buffering limits apply only to conversation routes, not image or other non-tool responses. Observe mode forwards SSE chunks immediately while retaining only bounded inspection state.

Never serialize or enqueue `ToolCall`. Security events carry only `ToolCallMetadata` (protocol, direction, kind, and a typed call ID hash), with a bounded tool name and no arguments, result or provider error text. Events also retain built-in check IDs, versions and scope when available. Parameter originals and snippets are not persisted. Async usage jobs receive a fresh context so request tool parameters cannot be retained indirectly. No MCP customer endpoint or MCP upstream routing is registered.
